# FeedDeck 仪表盘前端重构提示词

## 项目背景

FeedDeck 是一个个人信息流仪表板，部署在 Cloudflare Pages 上，运行在 iPad mini（768×1024）的 Safari 中作为电脑副屏常亮显示。

**技术栈约束（必须严格遵守）：**
- 纯 HTML/CSS/JS，无框架，兼容 iOS 12 Safari
- 动画库：GSAP 3.12 + Flip 插件（已通过 CDN 引入）
- 图标：Material Symbols Outlined（已通过 Google Fonts 引入）
- 字体：系统字体栈 + Georgia/宋体显示体（见 base.css 变量）
- 部署目标：Cloudflare Pages（静态文件 + Functions）

**分工原则：**
- 此次任务由你（Claude Code）完成所有前端代码实现
- 动画的速度、曲线、缓动等参数由其他工具单独配置，你只需要实现动画的方向和结构（哪些元素动、从哪到哪、分几个阶段），不要硬编码动画时长和 easing

## 涉及的文件

| 文件 | 作用 |
|------|------|
| `src/dashboard.html` | 仪表盘主页面（本次重构的核心文件） |
| `src/css/base.css` | 全局设计 token、组件基础样式 |
| `src/js/api.js` | 后端 API 封装（不需要修改） |
| `src/js/app.js` | 共享工具函数：时钟、toast、确认框等（不需要修改） |

## 你需要做的

### 1. 重构 dashboard.html 的整体结构

当前所有代码（CSS + HTML + JS）都塞在一个 942 行的 HTML 文件里。请重构为更清晰的结构：

- 内联 `<style>` 中只保留 dashboard 专属样式（grid 布局、卡片内容样式）
- 全局可复用的样式保留在 `base.css`
- JS 逻辑保持在 `<script>` 标签内（因为是纯静态部署，不需要打包工具）

### 2. 完善自适应布局逻辑

**卡片优先级规则：**
```
热搜榜单 > 行业资讯 > 天气 > 社交媒体 > 待办事项 > 今日日程
```

**四种布局状态：**

| 状态 | 条件 | 可见卡片数 |
|------|------|-----------|
| S0 | 有待办 + 有日程 | 6 |
| S1 | 有待办 + 无日程 | 5 |
| S2 | 无待办 + 有日程 | 5 |
| S3 | 无待办 + 无日程 | 4 |

**判空标准：**
- 待办：`data.todos.items` 为空数组，或所有条目 title 为空白
- 日程：过滤今日事件后结果为空
- 天气和社交媒体不参与隐藏逻辑——它们始终显示（即使内容为空也保留卡片占位）

**各状态的网格配置：**

S0（6 卡）— 保持现状：
- 横屏：3×2，每卡 1×1
- 竖屏：2×3，每卡 1×1

S1（5 卡，无日程）：
- 横屏：热搜 + 资讯 + 待办 在第一行（各占 1 列），天气跨 2 列 + 社交占 1 列在第二行
- 竖屏：热搜 + 资讯 在第一行，天气 + 社交 在第二行，待办跨 2 列在第三行

S2（5 卡，无待办）：
- 横屏：热搜 + 资讯 + 日程 在第一行，天气跨 2 列 + 社交占 1 列在第二行
- 竖屏：热搜 + 资讯 在第一行，天气 + 社交 在第二行，日程跨 2 列在第三行

S3（4 卡）：
- 横屏竖屏统一 2×2：热搜 + 资讯 在第一行，天气 + 社交 在第二行

### 3. 动画方向（不指定速度和曲线）

实现三阶段动画流程：

**阶段 1 — 空态闪现：** 卡片内容先渲染空状态文案（"今日无日程"/"暂无待办"），停留一段时间后再退场。让用户知道"这个模块存在，今天没数据"。

**阶段 2 — 卡片退场：** 需要隐藏的卡片用透明度渐出 + 轻微缩小。两张同时退场时做交错（stagger）。退场完成后设置 `display: none`。

**阶段 3 — 布局补位：** 用 GSAP Flip 让剩余卡片从旧位置平滑过渡到新位置。

**反向恢复（数据回来时）：** 新卡片渐入 + Flip 让位，不需要空态闪现。

动画的具体时长、缓动曲线、stagger 间隔等参数用 CSS 变量或 JS 常量集中管理，方便后续统一调整。

### 4. 防抖机制

- 隐藏：连续 2 次轮询（约 60 秒）都判空才执行退场
- 显示：检测到有数据后立即恢复
- 维护 `emptyCounters` 计数器 per 卡片类型

### 5. 窗口旋转处理

监听 resize 事件（带防抖），旋转后重新检测状态并调用 `applyLayout()`，用 FLIP 动画保持平滑。

### 6. 页面加载动画

初始加载时所有卡片用 GSAP 做入场动画（从下方淡入 + 位移）。

## 不要做的事

- 不要引入任何框架或构建工具（React、Vue、Vite 等）
- 不要修改 `api.js` 和 `app.js`
- 不要修改 `base.css` 中已有的设计 token 和组件样式
- 不要硬编码动画时长和缓动曲线——用变量集中管理
- 不要改变卡片的 data-card 属性值
- 不要改变后端 API 调用逻辑
- 不要添加任何装饰性元素（渐变、光效、blob）

## 验证方式

完成后用 `npx wrangler pages dev src` 本地启动，确认：
1. 6 卡状态下横屏/竖屏布局正确
2. 手动清空待办或日程数据后，卡片正确隐藏，剩余卡片自适应补位
3. 旋转设备后布局正确切换
4. 数据恢复后卡片正确显示
5. 在 Safari 或 Chrome DevTools 的 iOS 模拟器中确认无 JS 报错
